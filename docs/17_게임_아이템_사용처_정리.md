# 경찰과 도둑 게임 아이템 사용처 정리

> 슈퍼마켓, 서점, 주얼리샵에 배치되는 판매용 아이템과 상호작용 아이템의 역할을 정리한 문서입니다.  
> 판매용 아이템은 도둑이 훔쳐 너구리 상인에게 판매하는 전리품이며, 상호작용 아이템은 경찰·도둑·동물 AI와 추격 및 방해에 활용합니다.

---

## 1. 공통 분류 기준

### 아이템 타입

| 타입 | 설명 |
|---|---|
| `SELLABLE` | 도둑이 훔쳐 너구리 상인에게 판매할 수 있는 전리품 |
| `INTERACTIVE` | 던지기, 설치, 유인, 방해 등에 사용하는 아이템 |
| `CONTAINER` | 다른 아이템을 보관하거나 랜덤 전리품을 제공하는 오브젝트 |
| `SECURITY` | 진열장, 경보 장치처럼 절도 난도를 높이는 오브젝트 |
| `ENVIRONMENT` | 도로, 가로등, 나무처럼 맵을 구성하는 환경 오브젝트 |

### 휴대 방식

| 휴대 방식 | 처리 방식 | 구현 |
|---|---|---|
| `POCKET` | 소형 아이템. 이동속도 감소 없음 | 구현 완료 — 속도 100%, 획득 0.4초 |
| `ONE_HAND` | 한 손 운반. 다른 손 상호작용 일부 제한 | 일부 구현 — 속도 90%, 획득 0.9초. 손 제한은 없다 |
| `TWO_HAND` | 양손 운반. 공격·투척·동물 명령 일부 제한 | 일부 구현 — 속도 76.5%, 획득 1.6초. 행동 제한은 없다 |
| `BULKY` | 크고 무거움. 이동속도 감소 및 위치 노출 증가 | 일부 구현 — 속도 60%, 획득 2.4초. 노출 증가는 없다 |

수치는 `docs/03_GAME_RULES.md` 8.1과 8.2가 기준이다. 코드는
`LootCarryType.cs`의 `LootCarryRules`와 `LootPickupProgress.cs`에 있다.

# 2. 슈퍼마켓

## 장소 콘셉트

- 저가부터 고가까지 가격대가 가장 다양하다.
- 한우 선물세트, 홍삼 팩, 햄 선물세트 등 한국 마트의 분위기를 살리는 품목을 배치한다.
- 상호작용 아이템이 많아 경찰과 도둑이 자주 충돌하는 핵심 장소로 사용한다.

# 3. 서점

## 장소 콘셉트

- 아이템 종류는 적지만 저가품과 고가품의 가격 차이가 크다.
- 일반 책 사이에 노트북, 희귀 고서, 마법책처럼 비싼 물건이 섞여 있어 탐색의 재미를 준다.
- 높은 서가 때문에 시야가 차단되며 작은 소리도 중요한 단서가 된다.
- 폭죽처럼 장소와 어울리지 않는 아이템을 넣어 코미디를 강화한다.

# 4. 주얼리샵

## 장소 콘셉트

- 가장 높은 가치의 아이템이 모여 있지만 진열장과 경보 때문에 털기 어려운 공간이다.
- 아이템을 꺼내기 전에 유리 진열장을 열거나 부수는 과정이 필요하다.
- 대표 목표물인 대왕 반지를 획득하면 사이렌이 울리고 일정 시간 경찰 이동속도가 증가한다.
- 반지, 보석, 금괴처럼 탑뷰에서도 실루엣이 분명한 오브젝트를 중심으로 구성한다.

## 대왕 반지 경보 이벤트

`LootAlarm`으로 구현했다. 수치는 `docs/03_GAME_RULES.md` 8.4가 기준이다.

| 단계 | 상태 |
|---|---|
| 1. 도둑이 대형 유리 진열장을 연다 | 구현 완료 — 1.1초, 30m 소음 |
| 2. 반지를 분리하는 순간 사이렌 | 구현 완료 — 120m 소음 사건 |
| 3. 경찰에게 주얼리샵 위치 표시 | 일부 구현 — 소음 링이 **빈 진열대**에 뜬다. 미니맵은 없다 |
| 4. 경찰 이동속도 증가 | 구현 완료 — 1.25배, 12초 |
| 5. 도둑 노출 | 구현 완료 — 4초. 주기적 노출은 없다 |
| 6. 최고 등급 보상 | 구현 완료 — `rare-jewel` 500골드. 별도 보너스는 없다 |

반지를 든 도둑의 이동속도 감소는 경보가 아니라 **휴대 방식**이 한다 (`짐짝`, 60%).
경보와 곱해지므로 경보가 울린 채 반지를 든 도둑은 둘 다 적용받는다.

## 시각적 표현 규칙

- 반지는 일반 반지보다 크게 만들고 전용 케이스 안에 단독으로 배치한다.
- 목걸이는 진열판과 하나의 세트처럼 보이게 배치한다.
- 루비, 사파이어, 에메랄드는 현실보다 약 1.5~2배 크게 표현한다.
- 금괴와 왕관은 멀리서도 종류를 알 수 있도록 실루엣을 단순하게 유지한다.
- 진열장 유리는 실제보다 크고 만화적으로 표현해 내부 아이템이 가려지지 않게 한다.
- 유리와 내부 아이템은 별도 오브젝트로 분리해 파손 및 획득 애니메이션을 구현한다.

## 8.1 상세 문서화 기준

이 절은 위 자산을 실제 게임 규칙으로 확정하는 문서가 아니라, 현재 저장소의 구현 상태와 향후 활용 후보를 분리해 기록하는 자산 활용처 문서다. 자산 파일이 존재한다는 사실만으로 게임 기능이 구현되었다고 판단하지 않는다.

### 구현 상태 표기

- **구현 완료:** 현재 코드와 플레이 흐름에서 해당 자산의 기능이 검증된 상태.
- **일부 구현:** 관련 상태·시스템은 있으나 해당 자산 또는 전체 상호작용 연결이 없는 상태.
- **기획 확정:** 제품 방향과 MVP 문서에서 사용 목적이 채택되었으나 구현 전인 상태.
- **기획 검토:** 활용 후보는 있으나 효과·규칙·밸런스가 아직 확정되지 않은 상태.
- **미구현:** 활용 방향은 기록했지만 연결된 게임 로직을 확인하지 못한 상태.
- **확인 필요:** 자산명, 의도 또는 구현 연결이 서로 충돌해 먼저 확인해야 하는 상태.

### 현재 공통 연결점

- 기존 투척 규칙은 `Assets/_Project/Scripts/Gameplay/Items/ThrowableKind.cs`, `ToolUseAction.cs`, `ThrowResolver.cs`에 있으며 `Rock`, `Banana`, `GlueTrap`, `SensorLight`만 등록되어 있다.
- 기존 설치형 규칙은 `PlacedTrap.cs`와 `NetworkItemCoordinator.cs`의 함정·센서 중심 구현이다. 바리케이드, 교통콘, 랜턴, 상자와 같은 물리 오브젝트가 연결되었다고 보지 않는다.
- 강아지 명령은 `CompanionCommandId`, `CompanionCommandResolver`, `CompanionCommandDispatcher`를 사용하고, 고양이 `DISTRACT`는 `DistractionBoard`를 사용한다. 새 자산의 AI 반응은 이 시스템에 직접 연결되어 있지 않다.
- 발자국은 `ThiefScentTrail.cs`가 도둑 위치를 기록하고 `ScentTrailView.cs`가 시각화하는 일부 구현이 있다. 새 발자국 FBX가 해당 시각화에 연결된 것은 아니다.
- 경찰 손전등은 `PoliceFlashlight.cs`, `FlashlightCone.cs`, `FlashlightVisibility.cs`, `FlashlightConeView.cs`로 시야·노출 규칙이 일부 구현되어 있다. 새 FBX는 프리팹 또는 코드에 연결되지 않았다.
- 전리품은 `LootDefinition`, `LootItem`, `LootCarrier`, `LootHidingSpot`으로 획득·운반·숨김·판매가 구현되어 있다. 로우폴리 가방이 용량을 늘리는 아이템으로 연결된 것은 아니다.
- 네트워크 상태는 `NetworkItemCoordinator`, `NetworkPlayerLink`, `NetworkLootLink`가 Host 권한으로 동기화한다. 신규 자산 전용 네트워크 이벤트는 확인되지 않는다.

### 관련 게임 로직 현황

아래 분류는 신규 자산을 실제 기능으로 연결할 때의 재사용 가능성을 뜻하며, 자산 자체의 현재 구현 상태와는 별개다.

| 기능 | 현재 확인 내용 | 향후 연결 분류 |
|---|---|---|
| 공통 아이템 데이터 | `LootDefinition`에 `carryType`이 있고 이동 속도와 획득 시간을 정한다 (`LootCarryType`, `LootCarryRules`). 가격·소음·경보 필드는 아직 없다. | 일부 수정 필요 |

- **구현 상태:** 기획 검토.
- **연결 코드 또는 자산:** 자산 디렉터리 `ArtSource/Blender/dog_interact/potion bottle 3d model/`; 모델 `potion+bottle+3d+model.fbx`; 텍스처 `potion+bottle+3d+model.fbm/potion+bottle+3d+model_basecolor.jpg` 존재. 기존 버프·디버프 아이템 코드와 직접 연결되지 않았다.

#### 빨간 깃발

- **분류:** `PLACE` / `GUARD` / `OWNER_COMMAND`.
- **사용 가능 캐릭터:** 경찰이 설치하고 강아지가 목적지 또는 경계 대상으로 인식하는 후보.
- **핵심 용도:** 강아지의 목적지·경계 지점을 시각적으로 지정하는 설치형 명령 보조물.
- **작동 방식:** 유효한 위치에 설치하면 강아지 `GUARD` 목표로 전달하고, 회수·만료·새 위치 지정 규칙을 검토한다.
- **AI 반응:** 강아지가 깃발 위치로 이동하거나 주변을 지키는 후보다. 현재 `GUARD` 명령은 존재하지만 실제 깃발 오브젝트 연결은 없다.
- **게임 활용:** 경찰이 통로·보물 주변의 순찰 지점을 지정하고, 도둑이 이를 피해 이동하도록 경로 선택을 만든다.
- **코믹 연출:** 강아지가 깃발을 지키려다 깃발을 물고 이동시키거나, 깃발 주변을 지나치게 엄격하게 도는 연출을 검토한다.
- **밸런스 제약:** 경찰당 동시 설치 수·지속 시간·최소 설치 거리·재설치 쿨타임을 제한한다. 깃발이 맵 전체를 자동 감시하게 만들지 않는다.
- **구현 상태:** 일부 구현. 강아지 `GUARD` 명령과 목표 개념은 있으나 물리 깃발의 설치·동기화는 미구현이다.
- **연결 코드 또는 자산:** 자산 디렉터리 `ArtSource/Blender/dog_interact/red flag 3d model/`; 모델 `red+flag+3d+model.fbx`; 텍스처 `red+flag+3d+model.fbm/red+flag+3d+model_basecolor.jpg` 존재. 후보 연결점은 `CompanionCommandResolver`와 설치형 네트워크 조정 코드다.

#### 해골

- **분류:** `INTERACTIVE` / `FEAR_OBJECT` / `CLUE`.
- **사용 가능 캐릭터:** 경찰·도둑이 배치하거나 던지는 후보, 강아지가 반응 대상.
- **핵심 용도:** 직접 전투 효과가 아닌 경계·공포·조사 반응을 유발하는 위치 노출 기믹.
- **작동 방식:** 강아지가 범위 안에서 해골을 인식하면 성격 또는 현재 상태에 따라 짖기·후퇴·주변 조사 중 하나를 선택하는 방식을 검토한다.
- **AI 반응:** 경계, 공포, 조사 중 어떤 반응을 사용할지는 기획 검토다. 현재 공포 대상 분류와 성격별 반응 코드는 없다.
- **게임 활용:** 강아지를 우회시키거나 짖음으로 위치를 노출하는 양면 기믹으로 활용할 수 있다.
- **코믹 연출:** 강아지가 해골을 보고 뒤로 물러나다가 호기심에 다시 다가가는 짧은 반복을 검토한다.
- **밸런스 제약:** 발동 범위·반응 지속 시간·재발동 대기시간을 제한하고, 강아지를 장시간 무력화하지 않는다.
- **구현 상태:** 기획 검토.
- **연결 코드 또는 자산:** 자산 디렉터리 `ArtSource/Blender/dog_interact/stylized skull 3d model/`; 모델 `stylized+skull+3d+model.fbx`; 텍스처 `stylized+skull+3d+model.fbm/stylized+skull+3d+model_basecolor.jpg` 존재. 현재 공포 자극을 이 자산과 연결하는 코드는 없다.

#### 테니스공

- **분류:** `THROW` / `FETCH` / `TOY`.
- **사용 가능 캐릭터:** 경찰·도둑이 던질 수 있는 후보, 강아지가 반응 대상.
- **핵심 용도:** 가장 예측 가능한 강아지 물어오기·이동 유인 아이템이자 튜토리얼 후보.
- **작동 방식:** 던진 위치를 강아지의 임시 fetch 목표로 등록하고, 도착·회수·반환 여부를 상태로 관리하는 방식을 검토한다.
- **AI 반응:** 강아지가 공을 쫓아가고 물어오는 반응을 후보로 둔다. 현재 fetch 상태와 반환 보상은 없다.
- **게임 활용:** 이동 경로 조절과 기본적인 유인 규칙을 튜토리얼에서 설명하는 데 적합하다.
- **코믹 연출:** 강아지가 공을 물고도 돌려주지 않고 혼자 노는 반응을 낮은 확률로 검토한다.
- **밸런스 제약:** 투척 거리·반응 우선순위·반환 제한·재사용 대기시간이 필요하다. 추적·경계 명령을 매번 무효화하지 않는다.
- **구현 상태:** 기획 검토.
- **연결 코드 또는 자산:** 자산 디렉터리 `ArtSource/Blender/dog_interact/tennis ball 3d model/`; 모델 `tennis+ball+3d+model.fbx`; 텍스처 `tennis+ball+3d+model.fbm/tennis+ball+3d+model_basecolor.jpg` 존재. 기존 투척 파이프라인은 후보로 사용할 수 있으나 fetch AI와 연결되지 않았다.

## 8.4 경찰 소품 자산

#### 야구방망이 폴더(확인 필요)

- **분류:** 분류 확인 필요. 폴더명 기준 `INTERACTIVE` 후보.
- **사용 가능 캐릭터:** 경찰 장비 후보. 실제 아이템명이 야구방망이인지 확인 전까지 확정하지 않는다.
- **핵심 용도:** 실제 방망이 자산이라면 근거리 넉백 또는 짧은 경직으로 도둑의 행동을 취소하고 거리를 확보하는 비살상 장비 후보.
- **작동 방식:** 근거리 판정 후 짧은 행동 방해와 과장된 피격 연출을 적용하는 방식을 검토한다. 장시간 기절이나 직접 피해는 현재 방향에 포함하지 않는다.
- **AI 반응:** 동물 AI 대상 효과는 별도 정의하지 않는다. 도둑의 행동 취소·짧은 경직이 필요할 수 있다.
- **게임 활용:** 체포 직전 도둑의 도주 행동을 끊거나, 좁은 통로에서 거리를 만드는 장비 후보다.
- **코믹 연출:** 방망이 휘두르기보다 도둑이 빙글 돌거나 모자가 튀는 짧은 반응을 검토한다.
- **밸런스 제약:** 사거리·선후딜·쿨타임·경직 시간·벽 관통 여부를 제한하고, 연속 기절과 즉시 체포를 방지한다.

| 물약병 | 모델과 텍스처는 있으나 효과 종류·랜덤 여부·기존 버프 정의가 확인되지 않는다. | 효과를 확정하지 않고 확인 필요/기획 검토로 기록한다. |
| 야구방망이 폴더 | `bat 3d model` 디렉터리 내부 실제 모델은 `flashlight+3d+model.fbx`다. | `야구방망이 폴더(확인 필요)`를 유지하고 실제 아이템명을 변경하지 않는다. |
| 손전등과 랜턴 | 손전등은 이동형 방향성 조명 코드가 있고, 랜턴은 설치형 조명 자산만 있다. | 손전등은 이동·탐색, 랜턴은 설치·범위 통제로 역할을 분리한다. |
| 공사 바리케이드와 교통콘 | 둘 다 경로 차단 후보지만 크기·설치 속도·지속 시간에 차이를 둘 수 있다. | 바리케이드는 강한 장기 차단, 교통콘은 약한 신속 유도로 구분한다. |
| 골판지 상자와 나무 상자 | 골판지 상자는 도둑 위장, 나무 상자는 물리 엄폐·발판·장애물 후보로 성격이 다르다. | 상자 은신과 물리 오브젝트를 별도 상태로 기록한다. |

## 8.7 향후 구현 영향

이번 변경에서는 아래 항목을 구현하지 않는다. 실제 구현이 승인될 경우 필요한 영향 범위만 기록한다.

### 데이터 필드

현재 재사용 가능한 값은 기존 `LootDefinition`의 `stableId`, `displayName`, `rarity`, `ThrowableKind`의 사용 종류·효과·지속 시간·범위, `ThrowablePickup`의 `pickupId`·역할 제한, `LootItem`의 상태 값이다. 신규 공통 아이템 시스템을 만들 때는 다음 필드가 추가로 필요할 수 있다.

```text
itemId, displayName, category, usableBy, interactionType, targetType,
throwable, placeable, consumable, pickupable, duration, cooldown,
effectRange, noiseLevel, aiStimulusType, aiStimulusStrength,
implemented, assetPath
```

`LURE`, `DISTRACT`, `FETCH`, `TRACE`, `COMMAND`, `BUFF`, `DEBUFF`, `THROW`, `PLACE`, `BLOCK`, `REVEAL`, `CAPTURE`, `INVESTIGATE`, `CARRY`, `HIDE`, `CLIMB`과 `FOOD`, `SMELL`, `MOVING_OBJECT`, `LOUD_SOUND`, `TOY`, `CLUE`, `FEAR_OBJECT`, `OWNER_COMMAND`, `LIGHT`는 현재 값이 아니라 향후 후보 enum이다.

### 상태 머신

투척·설치·소비·운반·은닉을 통합하려면 `Available → Carried → Thrown/Placed → Active → Consumed/Expired/Dropped/Hidden/Sold`와 같은 상태가 필요하다. 현재의 투척·전리품 상태를 그대로 합치지 말고 아이템 유형별 허용 전이를 정의해야 한다.

### 충돌체

공·조형물·닭은 투척 충돌체와 이동 경로가 필요하다. 바리케이드·교통콘·랜턴·나무 상자는 설치 충돌체와 경로 재계산이 필요하다. 골판지 상자는 플레이어 은신용 충돌체와 시야 판정이 별도로 필요하고, 발자국은 실제 충돌체보다 단서 마커가 적합하다.

### 애니메이션

고양이의 몸 비비기·뒹굴기·공 쫓기, 강아지의 냄새 맡기·물어오기·공포·짖기, 경찰의 손전등·수갑·장비 사용, 도둑의 상자 착용·가방 운반·상자 밀기 표현이 필요하다. 게임 승패나 상태 전환은 애니메이션 이벤트가 결정하지 않는다.

### 사운드

기존 `GameSoundService`, `GameSoundObserver`, `GameSoundBank`에 투척·충돌·호루라기·삑 소리·랜턴 설치·무전기 잡음·수갑 체결 이벤트를 추가하는 방식을 검토한다. 소리 표현과 AI가 실제로 받는 `noiseLevel` 자극은 별도 데이터로 관리해야 한다.

### 네트워크 이벤트

클라이언트가 사용 요청을 보내면 Host가 역할·거리·쿨타임·대상·충돌을 검증하고, 아이템 상태와 효과를 동기화해야 한다. 기존 `NetworkItemCoordinator`와 `NetworkPlayerLink`를 확장하거나 유형화된 아이템 이벤트를 추가할 수 있지만, 이번 문서 작업에서는 네트워크 코드를 변경하지 않는다.

### AI 자극 시스템

현재 `DistractionBoard`, `PetCognitionResolver`, `ThiefScentTrail`을 후보로 재사용할 수 있다. 냄새·이동 물체·소음·장난감·공포·빛을 타입별 자극으로 전달하고, 고양이와 강아지가 같은 자극에 서로 다른 우선순위와 반응을 갖도록 상태 머신을 확장해야 한다. 입력 코드가 AI 상태를 직접 변경하지 않도록 기존 명령 디스패처 경계를 유지한다.

### 테스트

- 역할별 획득·사용·설치 권한과 잘못된 요청 거부
- 투척 거리·충돌·지속 시간·소멸·쿨타임·동시 설치 수
- 고양이와 강아지의 서로 다른 유인·소음·장난감·공포 반응
- 발자국 생성·추적·가짜 흔적 및 기존 `TRACK` 회귀
- 손전등·랜턴의 시야 및 은신 노출 회귀
- 수갑 선행 조건·체포 취소·권총 비살상 경직과 체포 연계
- 가방 운반 용량·속도 페널티·전리품 드롭·판매 회귀
- Host/Client 상태 동기화와 지연·중복 요청·권한 위조
