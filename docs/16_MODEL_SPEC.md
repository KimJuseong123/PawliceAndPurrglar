# 캐릭터 모델 제작 규격 (MODEL-001)

마지막 갱신: 2026-07-27

이 문서는 Blender에서 캐릭터를 제작할 때의 확정 규격이다. 여기서 벗어난 모델은
`Paws & Loot > Setup > Validate Authored Models`가 경고로 잡는다.

규격을 바꾸려면 코드만 고치지 말고 이 문서와 `docs/14_DECISION_LOG.md`를 함께
갱신한다.

## 1. 단위와 축

| 항목 | 값 |
|---|---|
| 스케일 | 1 Blender Unit = 1m, Unit Scale 1.0 |
| 원점 | 발바닥 중앙, 바닥 평면에 접함 (`z = 0`) |
| Blender Up | `+Z` |
| Blender Forward | `+Y` (캐릭터가 바라보는 방향) |
| FBX 내보내기 | `axis_forward="-Z"`, `axis_up="Y"` |
| Unity 결과 | Up `+Y`, Forward `+Z` |
| 적용 변환 | 내보내기 전 회전·스케일을 적용 (Apply Transform) |

내보내기는 저장소의 스크립트를 그대로 쓴다. 옵션을 직접 만지지 않는다.

```text
ArtSource/Blender/Props/export_props_fbx.py
```

## 2. 캐릭터 키

게임 코드가 임포트 후 목표 신장으로 정규화하지만, **제작 시점부터 맞춰두면
정규화 배율이 1에 가까워져 스키닝 왜곡이 줄어든다.**

| 대상 | 목표 신장 |
|---|---:|
| 경찰 | 1.70m |
| 도둑 | 1.70m |
| 강아지 | 0.75m (어깨 높이 기준) |
| 고양이 | 0.45m |
| 너구리 | 0.70m |

경찰과 도둑은 같은 키를 쓴다. 한쪽이 커 보이면 추격에서 심리적 유불리가 생긴다.

`2등신` 만화 비율을 목표로 한다. 머리가 전체 높이의 약 40~50%다.

## 3. 본 이름과 Root

### 사람형 (경찰, 도둑)

Unity Humanoid 자동 매핑이 성공해야 한다. 현재 반입된 모델이 통과한 이름
규칙을 그대로 쓴다.

```text
Root
  Hip / Pelvis
  L_Thigh  L_Calf  L_Foot  L_ToeBase
  R_Thigh  R_Calf  R_Foot  R_ToeBase
  Waist  Spine01  Spine02
  NeckTwist01  NeckTwist02  Head
  L_Clavicle  L_Upperarm  L_Forearm  L_Hand
  R_Clavicle  R_Upperarm  R_Forearm  R_Hand
```

- **Root Bone은 반드시 `Root` 하나**이며 원점에 놓고 애니메이션하지 않는다.
  루트 모션은 사용하지 않는다. 이동은 `CharacterController`가 담당한다.
- `*Twist*` 보조 본은 스키닝 분산 전용이다. 게임 코드가 직접 회전하지 않으며,
  없어도 된다.

### 사족형 (강아지)

현재 강아지가 쓰는 규칙을 유지한다. 절차적 보행 코드가 이 이름으로 다리를
찾는다.

```text
Root
  Spine_0  Spine_1  Head_0
  0_Left_Limb_0..3   0_Right_Limb_0..3   (앞다리)
  1_Left_Limb_0..3   1_Right_Limb_0..3   (뒷다리)
```

- 앞다리는 접두사 `0_`, 뒷다리는 `1_`이다. 바뀌면 보행이 뒤집힌다.
- `_1`이 상단 관절(어깨·고관절), `_2`가 하단 관절(무릎·팔꿈치)이다.
  절차적 보행이 이 두 관절만 구동한다.

### 사족형을 사람형 리그로 만들지 않는다

Unity는 사족 리그에도 Humanoid Avatar를 만들어준다. 하지만 사람 걷기 클립을
리타게팅하면 **네발 동물이 뒷다리로 서 버린다.** 동물은 반드시 Generic으로
반입하고 다리를 직접 구동한다.

## 4. 텍스처와 머티리얼

| 항목 | 값 |
|---|---|
| 머티리얼 개수 | 캐릭터당 **1개** |
| 텍스처 | Base Color 1장 |
| 해상도 | 1024×1024 (권장), 최대 2048×2048 |
| 포맷 | PNG 또는 JPEG |
| UV | 단일 UV 세트, 겹침 없음 |
| 셰이더 | Unity에서 URP Lit로 재지정 |

머티리얼을 여럿으로 나누면 드로우 콜이 그만큼 늘어난다. 현재 씬은 이미 렌더러가
많아 `ART-012`가 머티리얼을 합치는 중이므로, **제작 단계에서 1개로 맞추는 것이
가장 저렴하다.**

노멀·메탈릭·러프니스 맵은 현재 사용하지 않는다. 필요해지면 이 문서를 먼저
갱신한다.

## 5. 폴리곤 목표

| 대상 | 삼각형 목표 | 상한 |
|---|---:|---:|
| 경찰 / 도둑 | 3,000 | 6,000 |
| 강아지 / 고양이 / 너구리 | 2,000 | 4,000 |
| 건물 1채 | 3,000 | 8,000 |
| 소품 | 300 | 1,000 |

건물 상한이 특히 중요하다. 현재 반입된 건물은 렌더러가 채당 200~370개로
과다하며, 이것이 `ART-012` 최적화의 주된 대상이다. **건물은 부위별 오브젝트로
나누되 부위 개수는 10개 이하로 유지한다.**

## 6. 애니메이션 클립 이름

`ART-003` Animator가 이 이름을 찾는다. 대소문자를 포함해 정확히 일치시킨다.

| 클립 | 용도 | 필수 |
|---|---|---|
| `Idle` | 대기 | 필수 |
| `Walk` | 걷기 | 필수 |
| `Run` | 달리기 | 필수 |
| `Command` | 명령 발신·수행 반응 | 필수 |
| `Win` | 승리 | 권장 |
| `Lose` | 패배 | 권장 |

- 모든 클립은 **루트 모션 없이** 제자리에서 만든다.
- `Idle`, `Walk`, `Run`은 **루프**한다. 첫 프레임과 마지막 프레임을 일치시킨다.
- `Command`, `Win`, `Lose`는 루프하지 않는다.
- FBX 파일명은 `모델명@클립명.fbx` 규칙을 쓰거나, 한 파일에 모든 클립을
  담아도 된다. 후자를 권장한다.

## 7. 반입 경로

```text
ArtSource/Blender/Characters/   원본 .blend
Assets/_Project/Art/Characters/ 반입한 .fbx 와 텍스처
```

`.blend`를 런타임 에셋으로 직접 참조하지 않는다 (`DEC-009`).

## 8. 확정된 모델

다음 6종은 모델이 확정됐다. 교체 예정이 없으므로 프리팹과 Animator를 붙여도
재작업 위험이 없다.

```text
경찰, 강아지, 도둑, 고양이, 쓰레기통, 너구리
```

집과 그 외 건물·오브젝트는 **교체 가능성이 남아 있다.** 모델 자산에 직접
의존하는 구조를 만들지 않고 `PlaceholderModelLibrary` 경로를 유지한다.

## 9. 검사 방법

```text
Paws & Loot > Setup > Validate Authored Models
```

스케일, 원점, 리그 종류, 머티리얼 개수, 삼각형 수, 클립 이름을 검사하고 규격에
어긋나면 경고를 출력한다. 경고는 빌드를 막지 않는다. 규격을 의도적으로 벗어난
경우 이 문서에 예외를 기록한다.
