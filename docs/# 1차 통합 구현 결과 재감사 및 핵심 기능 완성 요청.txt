# 1차 통합 구현 결과 재감사 및 핵심 기능 완성 요청

현재 `19_INTEGRATION_IMPLEMENTATION_AUDIT.md`에는 Windows용 1차 Vertical Slice 구현 결과가 기록되어 있다.

현재 구현을 삭제하거나 처음부터 다시 만들지 말고, 기존 작업을 유지하면서 통합 개발 명세와의 차이를 정확히 조사하고 다음 단계 기능을 보완하라.

기준 문서:

* `경찰과_도둑_게임_통합_개발_명세서.md`
* `19_INTEGRATION_IMPLEMENTATION_AUDIT.md`

## 1. 현재 결과에 대한 판단 기준

현재 Windows 빌드는 다음 기능의 기반 구현으로 간주한다.

* 4칸 Tool Slot 데이터
* 1~4 퀵슬롯 선택
* 차징 투척 입력
* E/G 입력 분리
* Shift+1~4 동물 명령 디버그 입력
* 필수 명령 문자열 매칭
* MockTranscript 기반 V키 명령
* 일부 Network RPC

이를 전체 통합 버전 완료로 간주하지 않는다.

특히 다음 항목은 아직 완료되지 않은 것으로 취급하고 실제 코드를 조사한다.

* 실제 물리와 일치하는 투척 궤적
* 차징 게이지 및 착지 마커
* 직접 적중과 바닥 범위 효과
* 동물 유인 아이템
* 실제 마이크 녹음
* STT 및 LLM 연결
* 사용자와 동물 말풍선
* 동물 감정·상태 아이콘
* 필수 명령 8개의 실제 월드 행동
* 인벤토리와 컨테이너
* 미니맵과 경보
* Asset Registry
* 기존 Renderer, Rig, HUD 검증 실패

## 4. 기존 검증 실패 분류

현재 EditMode 7개와 PlayMode 12개 실패를 각각 조사한다.

각 실패에 대해 다음을 기록한다.

```text
테스트 이름
실패 메시지
관련 Scene 또는 Prefab
실제 플레이 영향
BLOCKER / HIGH / MEDIUM / LOW
수정 대상
```

다음을 우선 수정한다.

1. 역할별 Player Renderer 누락
2. HUD 설정 불일치
3. 현재 플레이 Scene에서 사용하는 건물 Renderer 누락
4. 강아지·고양이·도둑 Limb Driver 누락
5. Missing Reference 및 Missing Script

테스트를 통과시키기 위해 검증 조건을 제거하거나 테스트 범위를 임의로 축소하지 않는다.

오래된 테스트라고 판단할 경우 실제 에셋 구조가 변경됐다는 증거와 대체 테스트를 먼저 제시한다.

## 5. 차징 투척 완성

현재 cosmetic preview와 단순 4m~12m 거리 계산을 실제 물리 기반 투척으로 변경한다.

요구사항:

* 차징 게이지
* 최소·최대 차징
* 포물선 예상 궤적
* 예상 착지 마커
* 장애물 충돌 반영
* 예상 계산과 실제 Rigidbody 투척이 동일한 계산 사용
* 사람, 강아지, 고양이 직접 적중
* 바닥 착지 이벤트
* 착지 범위 효과
* 동일 충돌 중복 처리 방지

다음 흐름을 사용한다.

```text
ThrowChargeController
→ ThrowTrajectorySolver
→ Preview
→ Launch Velocity
→ Rigidbody Throw
→ DirectHit / LandingEffect
```

예상 궤적과 실제 궤적의 허용 오차를 PlayMode 테스트로 검증한다.

## 6. 아이템 유인 효과

아이템은 다음 기준으로 처리한다.

```text
effectTargets
activationTypes
effects
radius
duration
strength
```

최소 테스트 아이템:

* 뼈다귀: 강아지 유인
* 참치캔: 고양이 유인
* 고무닭: 강아지 혼란
* 깡통 또는 병: 사람 경직 및 소음 발생

직접 맞은 경우와 바닥에 던진 경우를 구분한다.

추격 중인 강아지의 반대 방향에 뼈다귀를 던졌을 때, 설정된 유혹 점수가 추격 집중도보다 높으면 강아지가 추격을 중단하고 뼈다귀 위치로 이동해야 한다.

## 7. Mock 음성 흐름 가시화

실제 API 연결 전에도 다음 흐름이 화면에서 보여야 한다.

```text
V키
→ Recording UI
→ MockTranscript
→ 사용자 말풍선
→ CoreCommandMatcher
→ Command Validator
→ 동물 해석 말풍선
→ 실제 동물 행동
→ 감정 아이콘
→ 성공 또는 실패 피드백
```

필수 UI 상태:

```text
Idle
Recording
Transcribing
Interpreting
CommandAccepted
CommandConfused
Failed
```

사용자 위에는 인식 문장을 표시한다.

동물 위에는 실제로 실행할 해석을 표시한다.

대상 또는 이동 경로가 없으면 임의 행동하지 말고 실패 이유를 표시한다.

## 8. 필수 명령 8개 행동 테스트

문자열 매칭 테스트만으로 완료 판단하지 않는다.

각 명령에 대해 실제 월드 행동 PlayMode 테스트를 추가한다.

### 강아지

* `DOG_SCENT_TRACK`
* `DOG_GUARD`
* `DOG_CHASE`
* `DOG_BITE`

### 고양이

* `CAT_CLIMB_ROOF`
* `CAT_SCRATCH`
* `CAT_SCREAM`
* `CAT_FIND_HIDEOUT`

각 테스트는 다음을 확인한다.

```text
명령 매칭
대상 또는 위치 해석
AnimalCommandRouter 전달
상태 전환
NavMesh 또는 행동 수행
성공 또는 실패 피드백
```

`CAT_SCREAM`은 실제로 강아지의 집중도 또는 냄새 추적 상태를 변경해야 한다.

## 10. 실제 음성은 별도 Adapter로 연결

Mock 경로를 유지한 상태에서 다음 인터페이스를 확인하거나 추가한다.

```text
IVoicePlatformAdapter
ISpeechToTextService
ILLMCommandService
```

구현 분리:

```text
MockVoiceAdapter
StandaloneVoiceAdapter
WebGLVoiceAdapter
```

WebGL 구현에서는 다음을 검증한다.

* 브라우저 마이크 권한
* HTTPS
* getUserMedia
* Unity JavaScript Bridge
* 오디오 데이터 전달
* STT 백엔드 요청
* CORS
* API 키 비노출
* 실패와 타임아웃
