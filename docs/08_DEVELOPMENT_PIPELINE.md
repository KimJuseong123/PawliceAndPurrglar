# 개발 파이프라인

## 단계 0. 방향과 문서 고정

작업:

- 제목과 한 줄 소개
- 3D 기울어진 탑다운 결정
- 4분 1대1 구조
- 너구리 상인 설정
- 숫자키 우선 명령 방식
- 문서와 저장소 구조

완료 조건:

- `AGENTS.md`, `README.md`, `docs/`, `prompts/`가 일관된다.
- 확정값과 가설값이 구분된다.
- 현재 상태와 다음 작업이 기록된다.

## 단계 1. 저장소와 Unity 기반 정리

작업:

- `Assets/_Project/` 구조 생성
- 외부 에셋 경계 확인
- Bootstrap, Game, Result 기본 씬 생성
- 렌더 파이프라인과 입력 설정
- 공통 설정 데이터
- 테스트 어셈블리

완료 조건:

- `Assets/_Project/Scenes/Bootstrap.unity`가 시작 씬으로 열린다.
- 공통 로더로 `Game`과 `Result` 씬을 이동할 수 있다.
- 그레이박스 오브젝트가 정상 렌더링된다.
- 컴파일 오류와 치명적 콘솔 예외가 없다.

## 단계 2. 경찰 리깅 기술 스파이크

작업:

- 기존 경찰 Blender 모델 정리
- 뼈 계층과 스킨
- Humanoid Avatar 검증
- `Idle`, `Run`, `ComedyRun`
- 루트 모션 비활성 이동 테스트

완료 조건:

- 경찰 프리팹이 올바른 축과 크기로 보인다.
- 세 애니메이션이 상태에 맞게 전환된다.
- 탑다운 시점에서 팔과 다리 움직임이 읽힌다.
- 실패와 경고가 문서에 기록된다.

이 단계는 최종 캐릭터 제작 단계가 아니다.

## 단계 3. 그레이박스 수직 슬라이스

작업:

- 작은 마을
- 경찰과 도둑 이동
- 카메라와 가림 처리
- 보물 1개
- 너구리 상인 판매 지점 1개
- 체포
- 강아지 `TRACK`
- 고양이 `DISTRACT`
- 숫자키 입력
- 결과 화면

완료 조건:

- 음성, 네트워크, 최종 모델 없이 한 경기를 처음부터 끝까지 완료한다.

## 단계 4. 핵심 게임 루프

작업:

- 보물 상태와 가격
- 상점과 경로
- 명령 각 4개
- 쿨타임과 실패 피드백
- 투척물 1종
- 코믹 방해 1종
- 역할별 HUD
- 재시작과 역할 교대

완료 조건:

- 각 진영이 동물 명령을 사용해야 하는 이유가 있다.
- 재시작 후 상태가 남지 않는다.
- 최소 5회 플레이테스트가 가능하다.

## 단계 5. 재미와 밸런스 검증

측정:

- 경찰과 도둑 승률
- 평균 경기 시간
- 평균 판매 금액
- 명령별 사용 횟수
- 상대를 찾지 못한 시간
- 추격 발생 횟수
- 체포 성공률
- 투척물 적중과 방해 시간
- 명령이 재미에 기여했다는 주관 평가

게이트:

- 핵심 루프가 재미없다면 음성과 최종 모델링으로 넘어가지 않는다.
- 문제를 규칙, 맵, 정보, 조작 중 어디에서 해결할지 기록한다.

## 단계 6. 멀티플레이 기술 검증

네트워크 방식이 확정된 뒤 진행한다.

검증:

- 두 플레이어 접속
- 역할 배정
- 이동 동기화
- 보물 소유권
- 판매와 체포의 단일 판정
- 경기 종료와 재시작
- 연결 종료 처리

핵심 규칙을 특정 네트워크 패키지에 직접 결합하지 않는다.

## 단계 7. 음성 입력 통합

구현 순서:

1. 숫자키와 버튼 명령 완성
2. `CompanionCommandId` 고정
3. STT 인터페이스
4. 텍스트 정규화
5. 명령 분류
6. 신뢰도 처리
7. UI 피드백
8. 실패 복구와 대체 입력

완료 조건:

- 음성과 숫자키가 같은 명령 결과를 만든다.
- 마이크 거부와 서비스 실패에도 경기를 완료한다.
- 낮은 신뢰도의 명령을 임의 실행하지 않는다.

## 단계 8. 최종 아트와 오디오

순서:

1. 역할과 실루엣
2. 동물 파트너
3. 보물과 너구리 상인
4. 건물과 가림 구조
5. 명령과 상태 VFX
6. 캐릭터 애니메이션
7. 오디오
8. 배경 장식

그레이박스 콜라이더와 프리팹 계약을 유지하면서 모델을 교체한다.

## 단계 9. 안정화

- 치명적 버그 수정
- 콘솔 오류 제거
- 빌드 반복 테스트
- 재시작과 역할 교대
- 네트워크 종료
- 마이크 거부
- 다양한 해상도
- 성능과 로딩
- 라이선스 확인

## 단계 10. 제출

- 최종 빌드와 실행 링크
- 소스 정리
- README 검증
- 30~60초 플레이 영상
- 게임 소개 문서
- AI 활용 기술 문서
- 팀 역할 기술서
- 대표 이미지와 스크린샷

## 작업 완료 공통 조건

- 요청 기능이 동작한다.
- 변경 범위에 맞는 검증을 수행한다.
- 오류와 경고를 확인한다.
- 관련 문서가 구현과 일치한다.
- 실행하지 않은 테스트를 실행했다고 기록하지 않는다.
