# 테스트 계획

## 1. 원칙

- 현재 구현 단계에 해당하는 테스트만 통과했다고 보고한다.
- 정적 문서 검사, Unity 컴파일, Edit Mode, Play Mode, 빌드 테스트를 구분한다.
- 음성과 네트워크가 미구현이면 관련 테스트는 `NOT RUN` 또는 `BLOCKED`로 기록한다.
- 실패를 숨기기 위해 테스트를 삭제하거나 조건을 약화하지 않는다.

## 2. 문서 테스트

- `AGENTS.md`와 `README.md` 존재
- `docs/00`부터 `docs/15`까지 존재
- 프롬프트 템플릿 존재
- 폐기된 판매 설정을 현재 설정처럼 사용하지 않음
- 4분 경기와 숫자키 우선 전략이 일관됨
- 확정값과 가설값이 구분됨
- `docs/13_CURRENT_STATE.md`가 실제 저장소 상태와 일치

## 3. 프로젝트 스모크 테스트

각 프로토타입 빌드 또는 주요 변경 후 수행한다.

- 지정 Unity 버전으로 프로젝트 열기
- 스크립트 컴파일
- 메인 씬 열기
- 그레이박스 정상 렌더링
- 경찰과 도둑 이동
- 카메라 추적
- 숫자키 명령
- 보물 획득
- 너구리 상인 판매
- 체포
- 경기 종료
- 재시작
- 치명적 콘솔 예외 없음

### 기반 구조 자동 검증

- 필수 게임 설정 에셋과 참조 검사
- 설정 수치 범위와 가격 순서 검사
- 개발 로그 레벨이 제출 로그 레벨보다 상세한지 검사
- 7개 로그 분류와 출력 접두사 검사
- 동일 `Once` 키의 중복 출력 억제 검사
- 프로젝트 코드의 빈 `catch`와 매 프레임 로그 호출 검사

### TECH-001 Windows 빌드

- `TechnicalTest` 씬 로드
- Windows x86_64 실행 파일 생성
- Input System 키보드 장치 확인
- 1280×720 창 모드 확인
- 실제 W 키 입력 후 큐브 이동 거리 기록
- 실행 결과 JSON과 스크린샷 생성

WebGL 로컬 서버와 GitHub Pages는 Windows 우선 단계에서는 `NOT RUN`이다.
WebGL을 다시 목표로 정할 때 별도 검증한다.

### TECH-002 Blender 연동

- Blender 5.2 배치 모드에서 `.blend`와 `.fbx` 생성
- Unity Generic 리그 임포트
- 5본, 단일 SkinnedMeshRenderer와 단일 재질 검사
- `Idle`, `Walk` 클립 이름 정규화와 Animator 재생
- 모델 높이 1.8m 이상 2.5m 이하
- 원점, 축, 회전과 `VisualRoot` 스케일 검사
- 이동 및 Collider가 `PlayerRoot`에 남아 있는지 검사
- 루트 모션 비활성화 검사
- 실제 WindowsPlayer 결과 JSON과 렌더 스크린샷 확인
- Edit Mode 모델 교체 계약 테스트

### TECH-003 Windows 음성 텍스트

- WindowsPlayer에서 마이크 장치 수 확인
- `DictationRecognizer` 생성과 듣기 상태 확인
- 인식 가설과 최종 텍스트 화면 표시
- 오류 메시지와 HRESULT 화면 및 JSON 기록
- 음성 실패 후 `Space` 대체 입력과 프로그램 응답 유지
- `tech-003-result.json`의 자동 하네스 결과와 수동 발화 결과 분리

현재 개발 PC 결과:

- WindowsPlayer 빌드: 성공
- 마이크 장치: 1개
- 키보드 대체 입력과 오류 화면: 통과
- 내장 recognizer 생성: 실패, `0x80004003`
- 실제 발화 텍스트: `NOT RUN`, recognizer 생성 불가

Windows 음성 언어 팩이 준비된 PC 또는 새 STT 후보에서 실제 한국어 문장이
표시되기 전에는 TECH-003을 통과로 처리하지 않는다.

## 4. 경찰 모델과 애니메이션

### 임포트

- FBX 축이 올바름
- 발 중앙이 원점
- 스케일이 맵 기준과 맞음
- 머티리얼이 분홍색으로 깨지지 않음
- 프리팹 참조가 유지됨

### 리그

- 필수 뼈가 연결됨
- 스킨 웨이트가 팔다리에서 깨지지 않음
- Humanoid Avatar가 유효함
- 유효하지 않으면 오류와 Generic 대안을 기록함

### 애니메이션

- `Idle`에서 발 미끄러짐 없음
- `Run`에서 이동 속도와 발 주기가 크게 어긋나지 않음
- `ComedyRun`에서 팔 실루엣이 탑다운에서 읽힘
- 루트 모션을 끈 상태에서 코드 이동 정상
- 상태 전환 시 캐릭터 순간이동 없음
- 재시작 후 Animator 상태 정상

## 5. 경기 상태

- `LOBBY -> READY -> PLAYING -> ENDING -> RESULT`
- 준비 중 이동과 상호작용 제한
- `ENDING` 이후 추가 판매와 체포 불가
- 결과가 한 번만 확정됨
- 재시작 후 타이머와 결과 초기화

## 6. 경찰 승리

### 시간 종료

1. 경기를 시작한다.
2. 도둑이 목표 금액에 도달하지 않는다.
3. 4분이 종료된다.
4. 경찰 승리와 정확한 이유가 표시된다.

### 체포

1. 경찰이 도둑에게 접근한다.
2. 체포 진행도를 완료한다.
3. 경찰 승리가 한 번만 판정된다.
4. 이후 판매 요청이 무시된다.

## 7. 도둑 승리

1. 도둑이 유효한 보물을 획득한다.
2. 너구리 상인 범위에서 판매한다.
3. 누적 금액이 목표에 도달한다.
4. 도둑 승리가 한 번만 표시된다.
5. 이후 체포와 추가 판매가 결과를 바꾸지 않는다.

## 8. 보물과 판매

- 빈손 획득
- 이미 소지 중 획득 거부
- 동일 보물 중복 획득
- 드롭 후 재획득
- 숨긴 보물 처리
- 판매 범위 밖 요청
- 중복 판매 요청
- 판매와 체포 동시 요청
- 경기 종료 후 요청
- 재시작 후 보물 위치와 상태

## 9. 체포

- 범위 진입
- 범위 이탈
- 장애물 뒤
- 대시로 탈출
- 경찰 행동 불능
- 도둑 행동 불능
- 경기 종료 직전 완료
- 판매와 같은 프레임에 완료
- 오브젝트 비활성화

- 숫자키별 올바른 명령 ID
- 다른 진영 명령 거부
- 대상 없는 명령
- 쿨타임 중 명령
- 연속 입력
- 기존 명령 중 새 명령
- 목표 소실
- 경로 없음
- 소유자 따라가기
- 명령 완료 후 복귀
- 경기 종료 중 명령
- 재시작 후 상태와 쿨타임 초기화

## 11. 카메라와 가시성

- 경찰과 동물 파트너가 함께 화면에 보임
- 추격 중 줌 변화가 과하지 않음
- 지붕과 벽이 플레이어를 장시간 가리지 않음
- 투척 궤적과 착탄 지점이 보임
- 화면 흔들림으로 조작 대상을 잃지 않음
- 16:9, 16:10, 창 모드 HUD 확인

## 12. 투척과 상태 이상

- 유효 물건 줍기
- 빈손 던지기 거부
- 궤적과 충돌
- 아군 또는 자기 자신 피격 규칙
- 연속 피격 제한
- 바나나 미끄러짐 종료 후 제어 복구
- 경기 종료 시 상태 이상 제거
- 재시작 시 투척물 정리

## 13. 향후 음성 테스트

음성 단계 전에는 실행하지 않는다.

- 정확한 명령
- 동의어
- 짧고 긴 문장
- 주변 소음
- 낮은 신뢰도
- 다른 진영 명령
- 마이크 권한 거부
- 마이크 없음
- 서비스 실패
- 음성과 숫자키 결과 비교

## 14. 향후 네트워크 테스트

네트워크 방식 확정 전에는 실행하지 않는다.

- 접속과 역할 배정
- 이동과 애니메이션
- 보물 소유권
- 중복 판매
- 동시 체포
- 경기 종료
- 지연과 패킷 중복
- 상대 연결 종료
- 재경기

## 15. 버그 심각도

### Critical

- 프로젝트 또는 빌드 실행 불가
- 한 경기 완료 불가
- 승패 판정 불가
- 반복적인 데이터 또는 상태 손상

### High

- 한 진영 플레이 불가
- 보물 판매 또는 체포 불가
- 핵심 동물 명령 불가
- 재시작 불가

### Medium

- 특정 조건의 명령 실패
- UI와 게임 상태 불일치
- 애니메이션 또는 모델 임포트 이상
- 일시적인 경로 문제

### Low

- 사소한 시각 문제
- 문구 오타
- 경미한 정렬 또는 오디오 문제
