# 18. 공모전 제출까지 남은 것

**마지막 실측: 2026-08-07.** 이 문서는 두 번 낡았고 두 번 다 방향이 달랐다 — 음성은
실제보다 **낙관적**으로, 나머지 기능은 **비관적**으로 적혀 있었다. 아래는 코드와 씬을
직접 세어 갱신한 것이다. **다음에 읽을 때도 수치는 다시 센다.**

## 0. 확정된 것

### 제출 플랫폼: **WebGL** (2026-08-07 확정)

음성이 컨셉의 핵심이고 브라우저 마이크 경로가 그것을 살리므로 WebGL로 간다. 따라오는
결과:

| 항목 | 결과 |
|---|---|
| 서버 | `server/`를 띄워야 한다. 심사 중에도 살아 있어야 한다 |
| https | **필수.** `navigator.mediaDevices`가 비보안 컨텍스트에 아예 없다 (`TASK-DEPLOY-004`) |
| API 키 | STT + 의도 해석. 아래 0-a |
| 용량 | 2026-08-06 실측 33.9MB. **"TopDownEngine 제거가 가장 큰 절감 수단"이라고 적혀 있었는데 그 에셋은 애초에 임포트된 적이 없다** — 실제 큰 항목은 참조와 무관하게 전부 들어가는 `Resources` 폴더였다 (`CLEAN-002`) |
| Windows 빌드 | **개발·테스트용으로 유지한다.** 같은 서버·같은 엔드포인트를 쓰도록 통합하는 것이 `VOICE-012`다 |

**Windows를 버리지 않는 이유**: 2인 실기 테스트와 2프로세스 회귀가 Windows 빌드에
붙어 있다. 전송을 플랫폼이 아니라 설정으로 고르면 Windows에서 개발하면서 **WebGL이 쓸
경로를 그대로 검증**한다. 이게 `VOICE-012`의 목적이고, WebGL 이관이 그때 URL 교체로
끝난다.

## 0-a. 음성 — 부품은 있고, 정확도가 없다

**이 문서의 첫 판은 "컨셉의 핵심이 통째로 비어 있다"고 적었다가, 두 번째 판은
"완성돼 있다"고 적었다. 둘 다 틀렸다.** 부품은 다 있지만 **받아쓰기 정확도가 못 쓸
수준**이라 시연이 안 된다 — 실측: `짖으라고` → `지지라고`, `숨어` → `스모`.
"파이프라인이 있다"와 "동작한다"는 다른 문장이다.

부품 목록은 정확했다:

| 실시간 소켓 | `Assets/Plugins/WebGL/VoiceBackendSocket.jslib` |

### (c-2) AI 생성 에셋 — 인수인계의 걱정에 대한 답

인수인계 문서가 **가장 중요하다**고 표시한 4번 질문("AI 생성 에셋 취급")의 답이 요강에
직접 적혀 있다.

> AI 도구 사용은 **허용·권장**하나, 사용 도구와 활용 내역을 반드시 기재해야 한다.
> 외부 에셋(이미지·사운드 등) 사용 시 출처와 라이선스를 **AI 활용 기술 문서에 반드시
> 명시**해야 한다.

따라서 **Tripo(모델)·Suno(BGM)·freesound CC0(효과음)는 사용 자체가 문제되지 않는다.**
금지되는 것은 *무단 도용*이고, 자기 계정으로 생성한 것과 CC0는 도용이 아니다. 조건은
하나뿐이다 — **`SUBMIT-004`에 도구 이름과 출처·라이선스를 빠짐없이 적는 것.** 이것이
선택이 아니라 **제외 사유**가 된다.

인수인계가 제기한 "순수 AI 생성물은 저작권 보호를 못 받는데 제6조 1항이 저작권을
참가자에게 귀속시킨다"는 긴장은 **남아 있지만 제출을 막지 않는다.** 요강이 요구하는
것은 소유권 주장이 아니라 **출처 고지**다. 그리고 이것은 법률 판단이므로 개발 쪽에서
결론을 내지 않는다.

**남은 실무는 `SUBMIT-005` 하나다**: 효과음 10종의 **freesound URL**, BGM 트랙의
출처·라이선스, **폰트** 라이선스. 지금 `docs/17_AUDIO_CREDITS.md`에 URL이 없다.
