# 18. 공모전 제출까지 남은 것

백로그 167개 항목(DONE 119 / TODO 38 / BLOCKED 10), 모델 149개, 문서를 훑어서
**제출 기준으로 비어 있는 것**만 모았다. 우선순위는 "없으면 제출이 안 되는가"와
"심사위원이 화면에서 알아채는가" 두 가지로 매겼다.

## 0. 먼저 결정해야 하는 것 세 가지

기능이 아니라 결정이다. 이게 안 정해지면 아래 작업의 절반이 방향을 못 잡는다.

### (a) 음성 — 이미 만들어져 있다. 문제는 플랫폼이다

**이 문서의 첫 판은 "컨셉의 핵심이 통째로 비어 있다"고 적었다. 틀렸다.**
백로그가 `VOICE-001`~`007`을 전부 `BLOCKED`로 두고 있었고 그것을 그대로 옮겼는데,
코드를 대조하니 음성 파이프라인이 **완성돼 있다.**

| 조각 | 위치 |
|---|---|
| 브라우저 녹음 | `Assets/Plugins/WebGL/VoiceMediaRecorder.jslib` |
| 실시간 소켓 | `Assets/Plugins/WebGL/VoiceBackendSocket.jslib` |
| 게임 쪽 입력 | `VoiceCommandInput`, `CompanionVoiceCommandBridge` |
| 서버 | `server/` (Node/TS, Dockerfile 포함) |
| 음성 → 텍스트 | `server/src/voice/speech-to-text-client.ts` (OpenAI) |
| 텍스트 → 의도 | `server/src/voice/intent-classifier-client.ts` (LLM) |
| 결정적 폴백 | `server/src/voice/exact-command-matcher.ts` + 테스트 |
| 음성 HUD | `VoiceCommandHudPresenter` (씬 배선됨) |

`TECH-003`(Windows 마이크)이 막힌 것은 사실이지만, **그것을 우회해서
브라우저 마이크 + 서버로 구현했다.** 백로그가 낡아서 막혀 있는 것처럼 보였을 뿐이다.

**그래서 진짜 결정은 "음성을 살릴까"가 아니라 "어느 플랫폼으로 제출할까"다.**

```text
VoiceCommandInput.cs:115   #if UNITY_WEBGL && !UNITY_EDITOR
```

녹음이 이 조건 안에 있다. **Windows 빌드에서는 컴파일 자체가 빠지므로 음성이
아예 없다.** 지금까지 플레이테스트한 Windows 빌드에 음성이 없었던 이유다.

| 선택 | 결과 |
|---|---|
| **WebGL 제출** | 음성이 산다. 서버를 띄워야 하고 OpenAI 키가 필요하다 |
| **Windows 제출** | 음성이 없다. 숫자키만 남고, 소개 문서에서 음성을 빼야 한다 |
| 둘 다 | 빌드 두 벌. 영상은 WebGL로 찍으면 된다 |

확인이 필요한 것: 서버 배포처, OpenAI 키의 출처와 비용, 심사 중 서버가 살아 있어야
하는지. **이건 기술이 아니라 운영 문제라서 팀이 정해야 한다.**

### (b) 승리 조건 확정

`THROW-012`(감옥)와 `THROW-013`(수갑 소모품)이 둘 다 "**승리 조건 결정과 함께**"로
묶여 대기 중이다. 지금은 체포 = 즉시 경찰 승리인데, 감옥이 들어오면 체포가 "20초
묶기"가 되고 경기 구조가 달라진다. 이건 밸런스가 아니라 게임의 형태다.

### (c) 공모전 요구 양식

`DOC-004` 공모전 요구 양식 반영이 **TODO**다. 제출물 규격(플랫폼, 영상 길이, 문서
양식, AI 활용 명시 의무, 권리 귀속)이 저장소 어디에도 적혀 있지 않다. **요강을
읽고 이 문서 아래에 옮겨 적는 것이 첫 작업이어야 한다** — 나머지 우선순위가 여기서

## 추천 순서 (대조 후 갱신)

1. **플랫폼 결정** (0-a) — WebGL이냐 Windows냐에 따라 음성이 있고 없다. 이것이
   소개 문서와 영상의 내용을 정하므로 가장 먼저다.
2. **`SUBMIT-005` 라이선스 마무리** — 모델은 Tripo AI 자체 제작으로 확인됐고
   증빙도 보관돼 있다. 남은 것은 BGM과 폰트 결정을 기록하는 것.
3. **관문 B 2인 실기 플레이테스트** — 승리 조건이 방금 바뀌었다(체포 3회). 4분,
   1,000골드, 3회가 맞는 숫자인지는 사람 둘이 해봐야 안다.
4. **`UI-009`** 체포 횟수와 구금 표시 — 3번을 하려면 사실상 필요하다. 화면에 안
   보이면 "왜 안 끝나지"가 된다. **팀원이 UI를 맡고 있으므로 그쪽에 넘긴다.**
5. **모델 배치** — 상점 진열·표정 아이콘. 위험 낮고 화면 변화가 가장 크다.
6. **`MERCHANT-001~003`** — 이동식 상인. 고정 판매처가 있으므로 급하지 않다.

`SUBMIT-001~004`(빌드·영상·문서)는 위가 끝나가는 시점에 시작한다. 영상은 게임이
바뀔 때마다 다시 찍어야 하므로 마지막이 맞다.
