# 18. 공모전 제출까지 남은 것

백로그 167개 항목(DONE 119 / TODO 38 / BLOCKED 10), 모델 149개, 문서를 훑어서
**제출 기준으로 비어 있는 것**만 모았다. 우선순위는 "없으면 제출이 안 되는가"와
"심사위원이 화면에서 알아채는가" 두 가지로 매겼다.

## 0. 먼저 결정해야 하는 것 세 가지

기능이 아니라 결정이다. 이게 안 정해지면 아래 작업의 절반이 방향을 못 잡는다.

### (a) 음성 명령을 살릴 것인가 — 가장 큰 건

이 게임의 컨셉은 **AI 동료에게 말로 명령하는 것**이다. 그런데:

| 항목 | 상태 |
|---|---|
| `TECH-003` Windows STT 격리 검증 | **BLOCKED** (`0x80004003`, 실제 발화 미검증) |
| `VOICE-001`~`007` (STT·정규화·분류·신뢰도·UI·실패대응) | **전부 BLOCKED**, 우선순위 P2 |
| 지금 동작하는 것 | 숫자키 `1`~`4` |

즉 **컨셉의 핵심이 통째로 비어 있고, 우선순위도 P2로 내려가 있다.** 셋 중 하나를
골라야 한다.

1. **STT를 되살린다** — 막힌 것은 Windows 음성 API 하나다. 대안(Whisper 로컬,
   클라우드 STT)으로 우회하면 컨셉이 산다. 가장 값어치 있지만 가장 비싸다.
2. **음성을 빼고 포지셔닝을 바꾼다** — "AI 동료와 함께하는 1대1 추격전"으로. 숫자키
   명령은 그대로 두고, 동료의 판단·경로 탐색 쪽을 내세운다.
3. **음성을 시연용으로만 붙인다** — 인식 정확도가 낮아도 영상에서 한 번 보여준다.

**아무것도 정하지 않으면 자동으로 2번이 된다.** 그건 괜찮지만, 그렇다면 소개
문서에서 "음성"을 빼야 한다.

### (b) 승리 조건 확정

`THROW-012`(감옥)와 `THROW-013`(수갑 소모품)이 둘 다 "**승리 조건 결정과 함께**"로
묶여 대기 중이다. 지금은 체포 = 즉시 경찰 승리인데, 감옥이 들어오면 체포가 "20초
묶기"가 되고 경기 구조가 달라진다. 이건 밸런스가 아니라 게임의 형태다.

### (c) 공모전 요구 양식

`DOC-004` 공모전 요구 양식 반영이 **TODO**다. 제출물 규격(플랫폼, 영상 길이, 문서
양식, AI 활용 명시 의무, 권리 귀속)이 저장소 어디에도 적혀 있지 않다. **요강을
읽고 이 문서 아래에 옮겨 적는 것이 첫 작업이어야 한다** — 나머지 우선순위가 여기서
바뀔 수 있다.

## 0-d. 백로그가 낡았다 — 이걸 먼저 고쳐야 한다

이 문서의 첫 판은 백로그의 `TODO`를 그대로 옮겨 적었다. 코드를 대조해 보니 **P0/P1
TODO 중 여섯 개가 이미 구현돼 씬에 배치되어 있다.**

| ID | 백로그 | 실제 | 근거 |
|---|---|---|---|
| `CAMERA-001` 탑다운 추적 카메라 | TODO | **동작** | `TopDownFollowCamera` 씬 참조 4곳 |
| `UI-004` 명령 슬롯·쿨타임 | TODO | **동작** | `CompanionCommandHudPresenter`, 화면의 `COMMAND [1/2]` |
| `UI-005` 명령 성공·실패 | TODO | **동작** | 같은 프레젠터, `✔READY` 표시 |
| `UI-008` 첫 경기 안내 | TODO | **동작** | `FirstPlayGuidePresenter`, 화면의 "1 키로 강아지에게 추적을 명령" |
| `THROW-002` 투척 궤적·착탄 | TODO | **동작** | `ThrowFlightTracker` |
| `LOOT-005` 보물 숨기기 | TODO | **동작** | `LootHidingSpot` 씬 배치 4곳 |

`MERCHANT-001~003`도 오해했다. **보물 판매 자체는 동작한다** (`LOOT-006`·`LOOT-007`이
DONE이고, 2프로세스 회귀가 매번 `soldAmount=200`을 기록한다). 비어 있는 것은 판매처가
아니라 **너구리 상인이라는 별도의 이동식 판매 수단**이다. 우선순위가 완전히 다르다.

**그러므로 첫 작업은 기능 추가가 아니라 대조다.** 낡은 백로그를 그대로 믿고 일하면
이미 있는 것을 다시 만들게 되고, 제출까지 남은 시간에 그럴 여유가 없다. 남은 `TODO`
38개를 코드와 하나씩 맞춰서 실제로 비어 있는 것만 남긴다. 반나절이면 끝나고, 그 결과가
이 문서의 나머지 우선순위를 다시 정한다.

## 2. 게임이 "완성돼 보이기" 위한 것

심사위원이 5분 안에 알아채는 순서대로.

### 2-1. 상점과 집이 비어 있다 — 가장 싼 개선

**모델 109개가 `ArtSource`에 있는데 Unity가 못 쓴다.** `Assets`에 40개가 있고,
씬이 실제로 배치하는 것은 **10개**뿐이다.

설명하지 않고 보여주는 유일한 수단이다.

## 4. UI — 대부분 이미 있다

`UI-004`(명령 슬롯·쿨타임), `UI-005`(성공·실패), `UI-008`(첫 경기 안내)은 전부 동작한다.
화면에 `COMMAND [1/2]`, `✔READY 따라오는 중`, "1 키로 강아지에게 추적을 명령"이 떠 있다.

남은 것은 다듬기다. 심사 영상 기준으로 부족한 것:

- **조작 키 전체 안내가 없다.** 첫 경기 안내는 동물 명령만 알려준다. 이동·대시·점프·
  상호작용·투척을 한 장에 보여주는 화면이 필요하다.
- 실내 조작(`Esc` 커서 해제, 카메라 회전)은 어디에도 안내가 없다.

## 5. 카메라 — 동작한다

있다. `CAMERA-002`(속도 기반 줌)와 `CAMERA-003`(가림 처리)은 실내에만 있고 실외에는
없다 — 실외 가림은 건물이 높지 않아 급하지 않다.

  트랙을 바꾸는 코드가 없다. 전환 지점(`MatchStateChanged` 등)은 이미 있다.
- `docs/16` B의 P0 7종(투척·명중·기절·센서·함정)은 ID조차 없다.

## 7. 검증

**관문 B(2인 실기 플레이테스트)가 아직 통과하지 않았다.** 자동 검증은
Edit 161 / Play 142 / 2프로세스 회귀가 전부 통과하지만, 사람 둘이 끝까지 한 판을
해본 기록이 없다. 제출 전에 반드시 해야 하고, 여기서 나오는 밸런스 문제는
지금까지의 어떤 테스트로도 안 잡힌다.
