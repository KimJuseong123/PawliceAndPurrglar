# 경찰과 도둑 게임 통합 개발 명세서

> 대상: Claude Code를 이용한 기존 Unity 프로젝트 분석 및 기능 확장  
> 문서 성격: 기획서가 아니라 **현재 프로젝트에 실제 기능을 연결하기 위한 구현 명세서**  
> 기본 원칙: 새 프로젝트를 만들지 않고, 기존 Scene·Prefab·Script·FBX·UI를 조사한 뒤 재사용한다.

# 1. 프로젝트 목적과 현재 전제

현재 프로젝트에는 플레이어 이동, 탑다운 카메라, E키 아이템 줍기, 아이템 던지기, 숫자키 기반 동물 명령, V키 녹음 등 일부 기능이 이미 구현되어 있다고 가정한다.

그러나 스크립트나 파일이 존재하는 것만으로 구현 완료라고 판단하지 않는다. 실제 Scene과 Prefab에 연결되어 있는지, Unity Editor와 WebGL 빌드에서 작동하는지 확인해야 한다.

이번 작업은 기존 시스템을 삭제하고 다시 만드는 작업이 아니라 다음 순서로 진행한다.

```text
현재 구현 조사
→ 실행 경로와 연결 상태 검증
→ 요구사항과의 차이 분석
→ 기존 구조를 유지한 기능 보완
→ Editor 및 WebGL 통합 테스트
→ 에셋·입력·기능 문서 갱신
```

게임의 핵심 경험은 다음과 같다.

- 플레이어는 경찰 또는 도둑을 조작한다.
- 경찰은 강아지, 도둑은 고양이와 함께 행동한다.
- 플레이어는 V키 또는 마이크 버튼을 통해 동물에게 음성 명령을 내린다.
- 핵심 명령 8개는 반드시 정확하게 수행한다.
- 핵심 명령 외의 자연어는 동물의 성격과 상황에 따라 정확 이해, 부분 이해 또는 오해가 발생한다.
- 플레이어가 말한 문장과 동물이 이해한 내용을 각각 말풍선으로 보여준다.
- 아이템을 주워 퀵슬롯에 장착하고, 차징하여 던지며, 사람이나 동물에게 직접 맞추거나 다른 방향으로 유인할 수 있다.
- 강아지와 고양이의 현재 상태는 머리 위 감정·상태 아이콘으로 확인할 수 있다.

초기 통합 버전에서 우선하는 것은 기능 연결과 플레이 가능성이다. UI 최종 외형은 이후 제공되는 레퍼런스 이미지에 맞춰 교체할 수 있도록 로직과 시각 요소를 분리한다.

# 2. 작업 전 필수 프로젝트 감사

코드를 수정하기 전에 저장소 전체를 조사한다. 현재 단계에서 확인되지 않은 기능은 추측하지 않고 `미확인`으로 기록한다.

## 2.1 조사 항목

1. 실제 Unity 버전과 렌더 파이프라인
2. 현재 실행 Scene과 시작 Scene
3. Build Settings에 포함된 Scene 순서
4. 플레이어 이동 및 역할 구분 방식
5. 입력 시스템과 Input Action 연결 상태
6. 탑다운 카메라와 건물 내부 표시 방식
7. NavMesh 또는 경로 탐색 방식
8. E키 아이템 줍기 구현
9. 아이템 들기·장착·내려놓기 구현
10. 아이템 던지기와 물리 충돌 구현
11. 숫자키 1~4 동물 명령 구현
12. V키 녹음 시작·종료 구현
13. 마이크 권한 처리
14. STT 요청 및 응답 처리
15. LLM 또는 명령 분류기 연결
16. 강아지·고양이 상태 머신과 행동 코드
17. 사용자 발화 및 동물 해석 결과 UI
18. 인벤토리·퀵슬롯·컨테이너 코드
19. 미니맵·덫·경보 코드
20. 캐릭터·동물·건물·아이템 FBX와 Prefab 연결
21. Resources, Addressables, StreamingAssets 사용 여부
22. WebGL JavaScript Plugin 또는 브리지

24. 컴파일 오류, Missing Script, Missing Reference

제거된 TopDown Engine 또는 현재 사용하지 않는 외부 프레임워크를 다시 의존성으로 추가하지 않는다.

# 3. 개발 원칙

## 3.1 기존 구현 우선

- 새로운 시스템을 만들기 전에 같은 역할의 클래스, Prefab, ScriptableObject, Event를 검색한다.
- 이미 작동하는 E키 줍기 기능을 새로 만들지 않고 확장한다.
- 던지기 코드가 존재한다면 차징, 예상 경로, 착지 표시, 아이템 효과만 보완한다.
- 녹음 코드가 존재한다면 V키 입력부터 STT·명령·AI 행동까지 끊긴 지점을 연결한다.
- 기존 Scene 전체를 재생성하지 않는다.
- 기존 Prefab을 덮어쓰기 전에 Variant 또는 백업 방식을 검토한다.
- 에셋 파일을 임의로 삭제하거나 이름만 일괄 변경하지 않는다.

## 3.2 모듈 분리

다음 시스템을 분리한다.

```text
Input
Interaction
Inventory
Equipment / QuickSlot
Throw
UI
Voice Recording
Speech-to-Text
Command Parsing
Command Validation
Animal AI
Emotion / Feedback
Minimap
Alert
Character Role
Asset Registry
```

UI 코드에서 직접 게임 상태를 변경하지 않는다. UI는 Controller 또는 Service에 요청하고 이벤트를 구독한다.

## 3.3 데이터 중심 설계

아이템, 동물 명령, 상태 아이콘, 모델 연결은 프로젝트에서 이미 사용하는 데이터 구조를 우선 사용한다. 적절한 구조가 없다면 ScriptableObject 또는 JSON 기반 레지스트리를 추가한다.

## 3.4 외부 AI의 권한 제한

LLM은 Transform, Rigidbody, NavMeshAgent, Animator를 직접 조작하지 않는다.

LLM은 제한된 Command JSON만 반환한다.

```text
음성 텍스트
→ 명령 해석 결과
→ Command Validator
→ 게임 내부 명령 객체
→ Animal AI 상태 머신
```

## 3.5 완료 판단

다음 조건 없이 기능을 완료했다고 보고하지 않는다.

- 컴파일 성공
- Scene 또는 Prefab 연결 확인
- Editor 실행 확인
- 필요한 경우 WebGL 실행 확인
- 오류 상황 처리
- 테스트 방법 기록
- 변경 파일과 미완성 항목 보고

# 4. 기본 플레이 화면과 카메라

플레이 화면은 완전한 수직 탑다운이 아니라 약간 기울어진 탑다운 시점으로 구성한다.

요구사항:

- 캐릭터와 주변 오브젝트가 함께 보인다.
- 건물 내부 진입 시 내부가 충분히 보인다.
- 지붕과 높은 벽이 플레이어를 가리지 않는다.
- 필요하면 플레이어와 카메라 사이 오브젝트를 투명화한다.
- 카메라는 플레이어를 부드럽게 추적한다.
- 사다리·계단·창문 이동 시 급격히 흔들리지 않는다.
- 건물 내부와 외부의 카메라 거리 설정을 분리할 수 있다.
- 지붕 숨김, 내부 컷어웨이, 벽 투명화가 서로 충돌하지 않는다.

카메라 시스템이 이미 있으면 교체하지 않고 기능을 보완한다.

# 5. 입력 체계와 상태별 입력 제한

## 5.1 기본 입력

| 입력 | 기능 |
|---|---|
| 이동키 | 캐릭터 이동 |
| E 짧게 | 기본 월드 상호작용 |
| E 길게 | 수색 등 지속형 기본 상호작용 |
| G 짧게 | 동물·출입구 중심 특수 상호작용 |
| G 길게 | 문 따기 등 지속형 특수 상호작용 |
| Tab | 도둑·고양이 가방 열기/닫기 |
| ESC | UI 닫기 또는 행동 취소 |
| 1~4 | 퀵슬롯 선택 |
| V | 음성 녹음 시작/종료 |
| 마이크 버튼 | V키와 동일한 기능 |
| 던지기 입력 | 현재 프로젝트 입력을 조사 후 유지 또는 재매핑 |

E/G 분리는 현재 기본 명세로 사용한다. 향후 UI 테스트에서 E 하나로 통합하더라도 Interaction Resolver가 같은 구조를 사용할 수 있도록 키와 상호작용 로직을 분리한다.

## 5.2 숫자키 충돌 해결

숫자키 1~4는 퀵슬롯 전용으로 사용한다.

기존 동물 명령 단축키가 1~4에 연결되어 있다면 다음과 같이 변경한다.

```text
실제 플레이: V 음성 명령 또는 명령 UI
개발용 직접 명령: Shift + 1~4
선택적 대안: F1~F4 또는 Debug Command Panel
```

음성, UI 버튼, 개발용 키 입력은 모두 같은 `AnimalCommand` 객체를 생성해야 한다.

```text
Voice Input ─┐
Command UI ──┼→ AnimalCommandRouter → Animal AI
Debug Key ───┘
```

# 6. HUD와 퀵슬롯

## 6.1 미니맵

화면 우측 상단에 미니맵을 배치한다.

표시 대상:

- 현재 플레이어 위치와 방향
- 주요 건물과 경찰서
- 출입 가능한 건물
- 동료 동물 위치
- 경찰이 설치한 덫
- 경보 장치
- 경보가 발생한 위치와 방향
- 일정 시간 유지되는 경보 핑

경보 발생 시:

- 해당 위치 또는 미니맵 가장자리 깜빡임
- 짧은 효과음
- 경보 종류 아이콘
- 제한 시간 후 제거
- 경보가 많으면 최근 또는 위험도가 높은 경보 우선

## 6.2 4칸 퀵슬롯

화면 중앙 하단에 4칸 퀵슬롯을 배치한다.

각 슬롯 표시 정보:

- 아이템 아이콘
- 수량
- 슬롯 번호
- 선택 상태
- 사용 가능 여부
- 재사용 대기시간
- 사용할 수 없는 이유

`canUseInQuickSlot == true`인 아이템만 배치할 수 있다.

선택된 아이템은 Equipment 시스템을 통해 캐릭터 손에 표시한다. 빈 슬롯을 선택하면 현재 장착 아이템을 해제한다.

## 6.3 마이크 버튼 위치

퀵슬롯 오른쪽에 마이크 버튼을 배치한다.

현재 UI 외형은 임시 구현으로 두고, 이후 제공되는 UI 레퍼런스 이미지에 맞춰 Prefab과 스타일만 교체할 수 있도록 한다.

# 7. 상황 기반 상호작용 시스템

플레이어 주변의 상호작용 대상을 감지하는 `InteractionSensor`와 최종 대상을 결정하는 `InteractionResolver`를 사용한다.

감지 방식은 기존 프로젝트 구조에 따라 Trigger, SphereCast, OverlapSphere 중 선택한다.

대상이 여러 개면 다음 순서로 평가한다.

1. 현재 역할과 상태에서 상호작용 가능한가
2. 상호작용 우선순위
3. E/G 입력 종류
4. 플레이어가 바라보는 방향
5. 플레이어와의 거리
6. 장애물 또는 벽에 가려져 있는가
7. 현재 선택된 아이템과의 관계

선택된 대상은 외곽선 또는 하이라이트로 표시한다.

예시 프롬프트:

```text
[E] 아이템 줍기
[E 길게] 찬장 수색
[E] 옷장에 숨기
[E] 사다리 오르기
[G] 고양이 쓰다듬기
[G 길게] 자물쇠 따기
[G] 창문으로 나가기
```

지속형 상호작용은 이동, 피격, 기절, 대상 소실, 거리 이탈 시 취소할 수 있어야 한다.

공통 인터페이스 예시:

```csharp
public interface IInteractable
{
    string InteractionId { get; }
    InteractionType InteractionType { get; }
    int Priority { get; }

    bool CanInteract(InteractionContext context);
    string GetPrompt(InteractionContext context);
    float GetInteractionDuration(InteractionContext context);
    void Interact(InteractionContext context);
}
```

필요에 따라 다음 인터페이스를 사용한다.

```text
IPickupable
ISearchable
IHideable
ILockpickable
IClimbable
IPettable
IContainer
IExitPoint
IThrowableTarget
```

# 8. E키 및 G키 월드 상호작용

## 8.1 E키

### 아이템 줍기

- 짧게 E를 누르면 현재 선택된 바닥 아이템을 줍는다.
- 이미 구현된 줍기 기능을 유지하고 Inventory·QuickSlot과 연결한다.
- 퀵슬롯 전용 아이템은 빈 퀵슬롯에 우선 배치할 수 있다.
- 퀵슬롯이 가득 차면 일반 가방으로 이동한다.
- 가방도 가득 차면 실패 이유를 표시한다.
- 벽 너머 아이템이나 상호작용 범위 밖의 아이템은 주울 수 없다.

### 찬장·서랍장 수색

- E를 길게 눌러 수색한다.
- 원형 진행 바를 표시한다.
- 이동, 피격, 기절 시 취소한다.
- 완료 후 컨테이너 인벤토리를 연다.

### 은신

- 옷장, 침대 아래, 상자, 쓰레기통 등에 숨는다.
- 은신 중 일반 이동을 제한한다.
- 다시 E를 누르면 나온다.
- 은신처 수용 인원과 발각 규칙을 데이터화한다.

### 사다리

- 경찰과 도둑 모두 사용한다.
- 위·아래 도착 지점을 명시한다.
- 이동 중 일반 이동 입력을 제한한다.
- 캐릭터 겹침과 도착 지점 막힘을 처리한다.
- 애니메이션이 없으면 임시 이동을 먼저 적용한다.

## 8.2 G키

### 동물 쓰다듬기

- 친밀도 증가
- 긴장도 감소
- 명령 이해도 일시 증가
- 짧은 애니메이션
- 재사용 대기시간
- 추격 또는 전투 중 제한

### 문 따기

- 도둑이 잠긴 문에서 G를 길게 누른다.
- 문 난이도, 도구, 소음, 경보 장치, 취소 조건을 적용한다.

```text
도구 없음: 느리고 시끄러움
기본 도구: 보통 속도
고급 도구: 빠르고 조용함
```

### 창문 진입·탈출

창문 상태:

```text
OPEN
LOCKED
BROKEN
BLOCKED
PASSABLE
IMPASSABLE
```

깨진 창문 통과 시 소음과 흔적 이벤트를 발생시킬 수 있다.

# 9. 인벤토리·퀵슬롯·컨테이너

## 9.1 도둑 가방

- Tab으로 열고 다시 Tab 또는 ESC로 닫는다.
- 기본 5×5, 총 25칸
- 아이템 가격 표시
- Tooltip에 이름, 설명, 가격, 무게, 사용법, 고양이 운반 가능 여부, 퀵슬롯 가능 여부 표시
- 총 가치와 현재 용량 표시

무게는 이동 속도를 낮추는 방식이 아니라 **최대 운반 한도**를 제한하는 방식으로 구현한다.

```text
currentCarryWeight
maximumCarryWeight
```

최대치를 초과하면 아이템을 추가할 수 없으며 이유를 표시한다.

## 9.2 고양이 가방

- 기본 2×3, 총 6칸
- `canCarryByCat == true`인 아이템만 이동 가능
- 플레이어와 고양이 거리가 너무 멀면 이동 제한 가능
- 고양이가 기절·붙잡힘 상태면 접근 제한

## 9.3 컨테이너 인벤토리

컨테이너 데이터:

```text
containerId
containerType
slotCount
searchDuration
hasBeenSearched
lootTableId
noiseLevel
requiredTool
canBeResearched
```

한 번 수색한 컨테이너의 아이템이 다시 생성되지 않도록 한다.

## 9.4 드래그 앤 드롭

지원 경로:

- 도둑 가방 ↔ 퀵슬롯
- 컨테이너 ↔ 도둑 가방
- 도둑 가방 ↔ 고양이 가방
- 인벤토리 → 월드 드롭

UI 바깥에 버릴 때 데이터만 삭제하지 않고 실제 월드 Prefab을 생성한다.

아이템 이동은 트랜잭션처럼 처리한다.

```text
이동 가능 검사
→ 대상 슬롯 예약
→ 원본 슬롯 제거
→ 대상 슬롯 추가
→ UI 갱신
→ 실패 시 복구
```

다음을 방지한다.

- 아이템 복제
- 슬롯 밖 소실
- UI 종료 시 소실
- 두 인벤토리에 동시 존재
- 월드와 인벤토리에 동시 존재

# 15. 일반 자연어의 정확 이해·부분 이해·오해

핵심 명령 외의 자연어는 세 단계로 처리한다.

```text
EXACT
PARTIAL
MISUNDERSTOOD
```

## 15.1 오해에 영향을 주는 요소

- 문장이 너무 김
- 대상이 여러 개임
- 저기·거기·그쪽 같은 모호한 지시어
- 주변에 유사한 대상이 많음
- 동물이 흥분·겁먹음·기절 상태임
- 플레이어와 거리가 멂
- 주변 소음이 큼
- 최근 명령과 충돌함
- 동물 집중력이 낮음
- 근처에 강한 유인 아이템이 있음
- 친밀도가 낮음

오해는 단순 랜덤이 아니라 다음 유형 중 하나를 선택한다.

```text
TARGET_MISUNDERSTOOD
LOCATION_MISUNDERSTOOD
ACTION_MISUNDERSTOOD
PARTIAL_KEYWORD_ONLY
PREVIOUS_COMMAND_CONTINUED
DISTRACTED_BY_ITEM
DELAYED_RESPONSE
COMMAND_IGNORED
```

## 15.2 강아지 성격

- 냄새·소리·추적 명령을 잘 이해함
- 따라오기와 자리 지키기를 비교적 잘함
- 음식, 뼈다귀, 공에 쉽게 집중을 빼앗김
- 흥분 상태에서는 기다리기를 어려워함

## 15.3 고양이 성격

- 은신처와 좁은 공간 탐색에 강함
- 지붕과 높이 차를 활용함
- 긴 명령을 무시하거나 일부만 수행할 수 있음
- 위험하면 명령을 자의적으로 중단할 수 있음
- 마음에 들지 않는 명령에 느리게 반응할 수 있음

LLM 호출 실패 시 현재 행동을 유지하거나 안전한 기본 행동으로 복귀한다.

## 16.1 고양이 소리 지르기

`CAT_SCREAM`은 강아지에게 다음 효과를 줄 수 있다.

- 현재 추적 집중도 감소
- 냄새 추적 일시 중단
- 잘못된 방향 조사
- 짧은 혼란 상태
- 소리 발생 위치로 시선 또는 이동 전환

효과 강도와 지속 시간은 거리, 벽, 강아지 집중 상태에 따라 달라진다.

## 16.2 강아지 냄새 추적

냄새 단서는 플레이어의 이동 흔적, 도둑의 최근 위치, 은신처 진입 흔적, 냄새 아이템 등으로 생성할 수 있다.

강아지가 은신처 근처까지 냄새를 따라오면 경찰 플레이어에게 은신처 의심 표시를 제공한다.

# 17. 동물 감정 및 상태 아이콘

동물 머리 위에 현재 상태를 나타내는 아이콘을 표시한다. 아이콘은 장식이 아니라 AI 상태를 플레이어에게 설명하는 핵심 피드백이다.

| 상태 | 아이콘 예시 | 표시 방식 |
|---|---|---|
| 명령 이해 | 전구 | 약 1초 |
| 혼란 | 물음표 | 약 2초 또는 상태 중 유지 |
| 냄새 추적 | 코·냄새 구름·발자국 | 추적 중 유지 |
| 자리 지키기 | 깃발 | 상태 중 유지 |
| 대상 추격 | 느낌표·발자국 | 추격 중 유지 |
| 아이템 유인 | 하트 | 유인 중 유지 |
| 소리 감지 | 소리 파동 | 짧게 표시 |
| 기절·혼란 | 별·회오리 | 상태 중 유지 |
| 목표 발견 | 전구·번쩍이는 눈 | 짧게 또는 추적 전환까지 |
| 공격 | 붉은 느낌표 | 공격 중 유지 |
| 은신처 탐색 | 눈·집 | 탐색 중 유지 |

동시에 여러 상태가 발생하면 다음 우선순위를 적용한다.

```text
STUNNED
> ATTACKING
> CONFUSED
> FOUND_TARGET
> CHASING
> DISTRACTED
> COMMAND_RECEIVED
> SEARCHING
> IDLE
```

아이콘 시스템은 `AnimalEmotionState` 또는 기존 상태 이벤트를 구독하며, AI 코드가 직접 UI Prefab을 생성하지 않도록 한다.

# 18. 은신과 발각 규칙

## 18.1 기본 은신

- 옷장, 침대 아래, 상자, 쓰레기통 등 데이터로 등록된 장소만 은신 가능
- 은신 중 이동 제한
- 같은 은신처 수용 인원 설정
- 은신처 수색 시 발각 가능

## 18.2 경찰 시야 규칙

경찰이 도둑이 은신처에 들어가는 장면을 직접 봤다면 해당 은신처를 즉시 의심 상태로 만든다.

```text
Thief enters hideout
+ Police has line of sight
→ HideoutSuspected = true
→ 경찰 UI 또는 AI 조사 우선순위 증가
```

## 18.3 강아지 냄새 규칙

강아지가 냄새를 추적해 은신처 근처에 도착하면 다음 피드백을 제공한다.

- 은신처 근처 냄새 표시
- 강아지 머리 위 냄새 또는 발견 아이콘
- 경찰 미니맵 또는 화면에 의심 핑
- 즉시 확정 발각이 아니라 수색 유도

# 26. 필수 테스트 시나리오

## 26.1 기존 구현

- E키로 바닥 아이템을 주울 수 있다.
- 줍기 범위 밖이나 벽 너머 아이템은 주울 수 없다.
- 기존 Scene과 Prefab이 손상되지 않는다.

## 26.2 투척

- 최소·최대 차징 거리 차이가 보인다.
- 예상 궤적과 실제 궤적이 허용 오차 내에서 일치한다.
- 벽을 향해 던질 때 착지 마커가 벽 뒤에 표시되지 않는다.
- 강아지에게 유인 아이템을 직접 맞출 수 있다.
- 반대 방향에 던진 아이템으로 추격 경로를 바꿀 수 있다.
- 사람에게 맞췄을 때 적절한 효과가 한 번만 발생한다.

## 26.3 음성

- V키로 녹음 상태가 시작되고 다시 V키로 종료된다.
- 마이크 권한 거부 시 안내가 보인다.
- STT 결과가 사용자 말풍선에 표시된다.
- 동물 해석 결과가 동물 말풍선에 표시된다.
- Mock STT와 Mock LLM으로 API 없이 테스트할 수 있다.
- 필수 명령 8개는 LLM 없이도 동작한다.
- 일반 명령은 정확·부분·오해 결과가 구분된다.

## 26.4 동물 명령

- 강아지 냄새 추적
- 강아지 자리 지키기
- 강아지 쫓아가기
- 강아지 물기
- 고양이 지붕 오르기
- 고양이 할퀴기
- 고양이 소리 지르기
- 고양이 은신처 찾기
- 대상이 없을 때 임의 행동하지 않고 실패 이유 표시

## 26.5 은신

- 경찰이 도둑의 은신 장면을 보면 해당 은신처를 즉시 의심한다.
- 강아지가 냄새를 따라 은신처 근처에 도착하면 의심 표시가 발생한다.
- 경찰이 보지 못했고 냄새 추적도 없으면 즉시 발각되지 않는다.

## 26.6 인벤토리

- 퀵슬롯 1~4와 동물 Debug Key가 충돌하지 않는다.
- 도둑 가방과 고양이 가방 사이 허용 아이템만 이동한다.
- 최대 무게 초과 시 이동이 거부된다.
- 드래그 도중 UI를 닫아도 아이템이 복제·소실되지 않는다.
- 월드에 버린 아이템은 실제 Prefab으로 존재한다.

## 26.7 에셋

- Asset ID가 중복되지 않는다.
- 모델 파일명, Prefab, Scene 참조가 일치한다.
- 캐릭터와 동물의 Collider, Rig, Animator가 누락되지 않는다.
- 이름 변경으로 Missing Reference가 발생하지 않는다.

# 27. 첫 통합 버전 완료 조건

다음 조건을 모두 충족해야 한다.

1. 현재 프로젝트 구조 감사 결과가 기록되어 있다.
2. E키 아이템 줍기가 실제 Scene에서 작동한다.
3. 1~4 키로 퀵슬롯을 선택할 수 있다.
4. 동물 개발용 명령은 퀵슬롯과 충돌하지 않는다.
5. Tab으로 도둑·고양이 가방을 열고 닫는다.
6. 도둑 가방, 고양이 가방, 컨테이너 간 이동이 안정적으로 작동한다.
7. 최대 운반 무게 제한이 적용된다.
8. 아이템을 차징하여 던질 수 있다.
9. 차징 게이지, 예상 궤적, 착지점이 보인다.
10. 사람 또는 동물 직접 적중 효과가 작동한다.
11. 바닥 착지 유인·소리·냄새 효과가 작동한다.
12. V 또는 마이크 버튼으로 녹음을 시작·종료할 수 있다.
13. 사용자 인식 문장이 사용자 말풍선에 표시된다.
14. 동물이 이해한 내용이 동물 말풍선에 표시된다.
15. 강아지 필수 명령 4개가 정확하게 실행된다.
16. 고양이 필수 명령 4개가 정확하게 실행된다.
17. 일반 자연어의 부분 이해 또는 오해가 제한된 규칙 안에서 발생한다.
18. 동물 머리 위에 현재 상태 아이콘이 표시된다.
19. 강아지·고양이·사람용 상호작용 아이템 효과가 구분된다.
20. 은신 장면 목격과 냄새 추적에 따른 의심 규칙이 적용된다.
21. 미니맵에 플레이어, 동물, 덫, 경보 핑이 표시된다.
22. 모델 이름과 번호가 Asset Registry에 정리되어 있다.
23. Mock 서비스로 외부 API 없이 핵심 흐름을 테스트할 수 있다.
24. Unity Editor에서 지속적인 NullReferenceException과 MissingReferenceException이 발생하지 않는다.
25. WebGL 대상 기능은 실제 브라우저에서 확인되었거나 `BUILD_TEST_REQUIRED`로 명확히 기록되어 있다.

# 28. Claude Code의 첫 응답 형식

처음부터 대량 수정하지 말고 다음 형식으로 먼저 보고한다.

```text
1. 현재 프로젝트 구조와 Unity 버전
2. 현재 시작 Scene과 실행 경로
3. 재사용 가능한 기존 코드
4. 코드는 있지만 연결되지 않은 기능
5. 부분 구현 또는 고장 난 기능
6. 존재하지 않는 기능
7. 입력 키 충돌
8. 음성 처리 연결 상태
9. 던지기 처리 연결 상태
10. 동물 AI와 필수 명령 현황
11. 에셋·Prefab·모델 번호 현황
12. 제안 데이터 흐름
13. 수정할 기존 파일
14. 새로 만들 파일
15. 단계별 구현 순서
16. 데이터 손실·Scene 손상·WebGL 위험 요소
17. 첫 번째로 구현할 최소 범위
```

각 구현 단계가 끝날 때마다 다음을 보고한다.

```text
변경한 파일
구현한 기능
기존 기능을 재사용한 부분
테스트 방법
Editor에서 확인할 항목
WebGL에서 확인할 항목
아직 구현하지 않은 기능
발견된 문제
다음 단계
```

기존 파일 삭제, Scene 구조 대규모 변경, 패키지 버전 변경, 에셋 이름 일괄 변경이 필요하다면 먼저 이유와 대체 방안을 보고한다.

# 29. Claude Code에 바로 전달할 실행 지시

이 문서를 읽은 뒤 다음 규칙으로 작업한다.

1. 현재 단계에서는 먼저 프로젝트 감사를 수행한다.
2. 감사 없이 새 시스템을 대량 생성하지 않는다.
3. 기존 E키 줍기, 던지기, V키 녹음, 숫자키 명령 구현을 우선 검색한다.
4. 기존 기능의 실제 연결 상태를 확인한다.
5. 감사 결과와 기능 차이 목록을 먼저 보고한다.
6. 가장 작은 실행 가능한 기능 단위부터 수정한다.
7. 각 단계에서 컴파일과 실행을 확인한다.
8. 문서와 코드가 충돌하면 임의로 결정하지 않고 충돌 내용을 보고한다.
9. API가 없어도 Mock으로 전체 흐름이 실행되게 한다.
10. 최종 UI 이미지는 이후 제공될 예정이므로 현재는 기능과 교체 가능한 UI 구조를 우선한다.
